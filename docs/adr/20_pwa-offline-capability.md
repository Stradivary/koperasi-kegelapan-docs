# ADR-020: PWA with Service Worker for Offline App Shell

**Date**: 2026-06-01  
**Status**: Accepted

## Context

The application is browser-based (Web NFC requires Chrome on Android). Operators in the field may lose connectivity at any time. The app must be usable immediately — even if the CDN is unreachable — as long as the user has visited it once before.

Without a Service Worker, a browser app requires network access to load its HTML, JS, and CSS assets on every page load. In an offline scenario, the user would see "No internet connection" instead of the functional app.

## Decision

Deploy the application as a **Progressive Web App (PWA)** using `vite-plugin-pwa` and Workbox for Service Worker generation.

**What the Service Worker provides:**
- **App shell caching**: HTML, JS, CSS, and static assets are cached after first visit
- **Offline page load**: the app loads from cache even without network connectivity
- **Background update**: new versions are downloaded silently and activated on next navigation
- **Add to homescreen**: installable on Android as a standalone app-like experience

**What the Service Worker does NOT do:**
- No background sync of transactions (NFC requires foreground tab with active page)
- No push notifications
- No background NFC operations (Web NFC is foreground-only)

**PWA configuration:**
- Strategy: `generateSW` (auto-generated by vite-plugin-pwa)
- Runtime caching: network-first for API calls, cache-first for static assets
- Registration: via `workbox-window` with update prompt

## Consequences

**Positive:**

- App loads instantly even without network — critical for field operation
- Users can install to homescreen for app-like experience (no app store needed)
- Automatic background updates keep the app current without user intervention
- Combines with IndexedDB local-first architecture for complete offline capability

**Negative:**

- Service Worker lifecycle (install, activate, update) adds complexity to debugging
- Stale cache can serve outdated code if update detection fails
- iOS Safari has limited PWA/Service Worker support (but iOS doesn't support Web NFC anyway)
- Extra build step to generate SW manifest

**Risks:**

- A buggy Service Worker that caches error pages can make the app permanently broken (requires clear-site-data). Mitigated by proper cache versioning.
- Large app bundles increase initial cache time. Mitigated by code splitting.

## Alternatives Considered

| Option                        | Reason Rejected                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------- |
| **No PWA (plain web app)**    | Cannot load offline. Operators would be blocked on network outages.                   |
| **Native Android app**        | Requires Play Store distribution. Adds build complexity. Web NFC works fine in Chrome. |
| **Capacitor/Cordova wrapper** | Adds native bridge complexity without clear benefit. PWA achieves the same UX goals.  |
| **Electron (desktop)**        | Target is Android tablets, not desktop. Web NFC is Chrome-only.                       |
