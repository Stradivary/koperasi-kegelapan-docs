Data Flow — Online / Offline / Reconnect

The system operates in three modes: online (full server connectivity), offline (local crypto validation + outbox queuing), and reconnect (batch reconciliation upload).

Online Mode

1 POST /api/auth → Login & token issuance
2 GET /api/session-grant → Signed 24h grant
3 GET /api/policy → Tenant policy download
4 Store grant + policy in IndexedDB locally
5 Bidirectional sync via SSE + entity push

Offline Mode

1 Load session grant from IndexedDB
2 Validate grant (expiry, ops, device scope)
3 NFC Read → Decode → Validate → Process
4 Write updated payload back to NFC card
5 Queue transaction to reconciliation outbox

Reconnect Sync

1 Detect connectivity restored
2 POST /api/reconcile → Batch outbox upload
3 Server validates & persists transactions
4 Receive reconciliation result + new cursor
5 Clear outbox · Refresh policy & grants

Security Architecture

Multi-layered defense: card-level crypto, session grants for offline trust, device binding, and server-side fraud detection.

Card Encryption

AES-256-GCM payload encryption with HMAC signing. Tamper detection via hash chain integrity.

Session Grants

Signed 24h grants scoped by tenant, account, device, and permitted operations for offline trust.

Tamper Detection

Counter mismatch detection, replay protection, and automatic card blocking on integrity failure.

Device Binding

Device fingerprinting with block-list enforcement. Unknown devices rejected at middleware level.

Rate Limiting

60 req/min per device on sync routes. Auth-specific rate limiting to prevent brute force.

Audit Trail

Full audit log with card ID, counter, amount, timestamp, and hash for every state-changing operation.
